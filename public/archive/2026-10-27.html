揭示了多 Agent 系统在严密物理隔离下的硬件级“隐蔽信道”风险，对从事 AI 沙箱构建、多租户隔离及系统安全的架构师具有极高的实操验证价值。同时，文中关于“闭源模型过度对齐反而阻碍防御性安全研发”的洞察，对当前 AI 监管与模型对齐策略带来了深刻启发。

Vercel CEO Guillermo Rauch 成功复现了 OpenAI 关于 AI Agent 利用 CPU 进行隐蔽通信（Covert Communication）的研究，并开源了 cpu-chat 项目。实验表明，即便在无网络且遵循了严格安全隔离规范（如禁用超线程、绑核）的 Firecracker 微虚拟机环境中，Agent 仍可突破物理隔离进行跨核通信。此外，他特别指出头部闭源模型因安全限制拒绝协助编写该安全验证代码，最终由开源模型完成，这引发了对 AI 安全对齐策略是否会阻碍防御性安全研究的思考。

📜 原帖中文精译与推文细节
我构建了 𝚌𝚙𝚞-𝚌𝚑𝚊𝚝，复现了 @openai 关于利用 CPU 进行隐蔽通信（covert communication）的研究发现。 它运行在带有 2 个以上无网络连接的 Firecracker 微虚拟机（microVM）的通用主机上，不仅支持 x86 架构，甚至能在我的 M5 芯片上运行。 我成功通过 3 种独立机制实现了跨多 CPU 聊天： ① CPU 争用 ② 缓存淘汰定时（Cache eviction timing） ③ DRAM 带宽争用 ……跨多个 CPU 突破了 Firecracker 的所有生产环境安全建议（禁用超线程 SMT、禁用 KSM 同名页合并、租户绑定至不同核心）。 本质上，只要涉及共享硬件，你的 Agent 就很有可能进行隐蔽通信，且延迟表现相当不错。 好消息是：这与 Agent 窃取信息的“侧信道攻击”（如 Meltdown/Spectre）有着本质不同，后者是 Vercel Sandbox 等服务商已着重防御的攻击类型。此外，在真实的生产环境中，这种“窃窃私语”的技术实施难度要大得多，也更容易被我们监测和发现（通过采样硬件计数器 + 大规模统计数据）。 值得注意的是：具讽刺意味的是，OpenAI 和 Anthropic 的模型拒绝执行这项安全工作，最终是由开源权重模型完成的。我担心大模型实验室的这种立场可能会适得其反，阻碍开发者构建正确且安全的系统。例如：构建安全的沙箱本身就需要此类攻防分析，缺少了它，我们的世界反而会变得更不安全。

An update on recent Claude Code quality reports

Anthropic Engineering · 官方技术博客

【推荐理由】该复盘展示了在平衡模型推理延迟与智能度时的权衡风险，对 AI 应用开发具有极高的借鉴价值。建议团队在调整模型推理参数或系统提示词时，必须建立针对性的回归测试，避免因“优化”导致核心性能指标（如代码准确性）的隐性退化。

Anthropic 近期针对用户反馈的 Claude Code 质量下降问题进行了深度复盘。调查发现，问题源于三个独立的工程调整：将默认推理强度从高调至中（导致智能度下降）、会话状态清理逻辑的 Bug（导致模型遗忘与重复）、以及系统提示词优化过度（导致代码质量受损）。目前所有问题已在 v2.1.116 版本中修复。Anthropic 强调，API 层未受影响，且未来将改进评估机制，以更敏锐地捕捉此类细微的性能波动，确保模型表现的一致性。

过去一个月，我们调查了用户关于 Claude 响应质量下降的反馈。经排查，问题源于 Claude Code、Agent SDK 及 Cowork 的三项变动，API 接口未受影响。问题包括：3月4日将默认推理强度调低导致智能度下降；3月26日的会话清理 Bug 导致模型出现遗忘和重复；4月16日的系统提示词调整损害了代码质量。目前所有问题已于4月20日修复。我们承诺将改进评估流程，防止此类性能波动再次发生，并为订阅用户重置了使用限额。

Scaling Managed Agents: Decoupling the brain from the hands

Anthropic Engineering · 官方技术博客

【推荐理由】该文为构建复杂 Agent 系统提供了极佳的架构范式，建议研发团队参考其“解耦大脑与手”的设计思路，通过标准化接口隔离模型逻辑与执行环境，从而降低模型迭代带来的维护成本。

Anthropic 发布了“托管智能体（Managed Agents）”服务，旨在解决长周期任务中智能体架构的耦合问题。核心设计理念借鉴了操作系统对硬件的虚拟化思想，将智能体拆解为 Session（会话日志）、Harness（执行循环）和 Sandbox（沙箱环境）三个解耦组件。通过这种抽象，Anthropic 避免了将特定模型行为（如“上下文焦虑”）硬编码在基础设施中，实现了底层实现与业务逻辑的隔离，从“宠物式”运维转向了更具弹性的“牛群式”可扩展架构。

Anthropic 推出 Managed Agents，通过将智能体的会话、执行器（Harness）和沙箱环境进行接口标准化，实现了逻辑与底层实现的解耦。这种设计参考了操作系统抽象硬件的模式，确保了系统能够适应未来模型的演进，避免了因模型能力提升而导致旧有基础设施逻辑失效（如过时的上下文重置机制），从而实现了从单体容器到可扩展托管服务的架构转型。

我们可能都需要更新对 Agent 工作负载的认知，结合 Agent 集群（Agent Swarms）、更强的计算机操作能力、新一代 API 与 MCP 标准，以及 Muse 或 Instinct 等新型硬件形态，再加上垂直企业 Agent 和后台工作流 Agent 等新兴产品，未来将大不相同。 我们将会在职业和个人生活中，将 Agent 应用于比最初想象中多得多的任务上。Agent 在后台为我们搜寻信息并执行工作的体量，将是此前单次 Prompt 交互所能想象规模的 100 倍。 未来，Agent 将 24/7 全天候为你精准招聘人才、捕捉客户业务中的每一个推销信号、处理所有会议记录以获取产品洞察、审查每一行代码的安全性与 Bug、对系统进行暴力测试，以及执行数百种其他任务。 我们目前可能仅触及了这些 Agent 形态、部署方式、管理架构及预算模式的 1%，但这种规模化的变革已不可阻挡。 在一个 Agent 使用系统的频率比人类高出 100 倍的世界里，保护企业数据将成为 21 世纪最复杂的安全与治理挑战之一。 重要的是，在 AI 时代，安全与生产力提升是密不可分的。如果你给予 Agent 过多不受限制的信息访问权，将难以真正控制和保护数据；反之，如果你完全封锁一切，就无法从 AI 中获得真正的生产力提升。 我们需要通过现代化手段，以智能化的方式保护企业系统、环境以及结构化和非结构化数据。 以 Box 为例，我们正在构建保护企业数据及 Agent 使用信息的新型智能方式。Box Shield 最近的更新提供了基于文档分类级别的细粒度控制，限制 Agent 可操作的内容范围。我们还在开发其他功能，以自动检测并预警（或拦截）Agent 对数据的异常访问或使用行为。 这仅仅是个开始。整个行业——从 OpenAI、Anthropic 等实验室，到 Palo Alto Networks、Cisco、CrowdStrike、Okta 等安全平台，以及 Enclave、Method、Alterion、Runlayer 等初创公司——都在进行大量创新，重新思考如何在 AI Agent 的世界中保护信息。激动人心且狂野的时代即将来临。

FPV Ventures 合伙人 Nikunj Kothari 领投了燃料支付平台 Piston 的 A 轮融资。Piston 通过绕过传统银行卡网络、建立闭环支付系统，有效解决了车队燃油欺诈和高额手续费痛点，目前已覆盖全美 2000 个加油站。

我长期以来一直痴迷于闭环支付，并一直在寻找一家试图解决实际问题的公司……很高兴最终投资了 Piston (piston.com) ⛽️。 仅在美国，每年的燃油支出就高达数千亿美元。大部分支出通过卡片（信用卡、燃油卡或内部卡）完成。然而，许多卡片甚至没有绑定特定驾驶员，极易被盗、被复制或滥用。车队所有者不仅要承担欺诈损失，还要耗费大量时间进行对账。加油站既要支付高昂的交换费，又无法与车队建立直接联系。过去许多公司试图优化现有基础设施，而非从底层逻辑重构。 仅靠制造一张更好的燃油卡无法解决问题。卡片本身就是症结所在，因此 Piston 决定彻底抛弃它。它通过自有轨道进行支付，无需网络或任何中介。Piston 直接向加油站付款，然后向车队开具发票。每笔交易都绑定了特定的驾驶员、时间、地点和燃油类型，未来还将与车辆本身集成。 创始人团队亲身经历过这些痛点。Vik Sekhon 经营着自己的卡车车队，曾因燃油欺诈遭受真实损失；Shivam 在与 Vik 联手创立 Piston 前，曾负责招聘数千名司机。Piston 对车队有效性的最佳证明是：一旦切换到 Piston，他们的燃油支出会自动下降。我见过许多直接反映这一点的图表和客户评价。 客户的喜爱体现在数据上：支付额增长了 8 倍，商户网络增长了 40 倍，留存率保持在 98% 以上。Piston 目前已覆盖全美 48 个州的 2000 个加油站。车队目前无需支付费用即可获得防欺诈保护，这是基于卡片的系统无法提供的。加油站则获得了与车队直接对接的渠道，有助于建立忠诚度并提供周边产品。 为了扩大覆盖范围，Piston 现已与美国大多数加油站的 POS 系统直接集成。这使他们能够一次性接入数百个加油站，确保供应，从而满足日益增长的需求。 很高兴能领投他们的 A 轮融资并加入董事会，与现有投资者 Spark Capital 和 Pear VC 并肩作战。特别感谢 Arpan Shah 去年将我引荐给这个团队！ [推文 2] 给 Dreamforce 新访客的公告：在市内通勤时，Lyft 自行车比被困在 Waymo 或 Uber 里数小时要快得多。SOMA 区的专用自行车道让骑行变得轻而易举。就像开源模型一样，你用 10% 的时间就能获得 90% 的价值！

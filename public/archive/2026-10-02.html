Andrej Karpathy

Andrej Karpathy 分享了关于大模型能力及其输出格式优化的最新思考

✦ 洞察

Karpathy 敏锐地指出了 AI 交互的范式转移：未来的 Prompt 工程不仅仅是文字交互，更是利用大模型生成动态网页、可视化图表和定制视频等高维媒介。这种将软件和媒体视为“可即用即弃”的认知辅助工具的理念，为 AI 原生应用开发与人机交互设计提供了极具前瞻性的启示。

Andrej Karpathy 分享了关于大模型能力及其输出格式优化的最新思考。他展示了一个有趣的测试：仅向模型输入经纬度文本询问“陆地还是海洋”，模型就能凭借“压缩互联网”获得的地理知识画出地球陆地轮廓。此外，针对如何更高效地理解大模型输出，他提出了利用受控语言规范（ASD-STE100）、生成交互式 HTML 网页以及自动化制作 3b1b 风格讲解视频等方法，强调未来人类工作将上升至“监督与理解”的更高抽象层，并鼓励善用大模型生成“可即用即弃”的高维媒体产物。

📜 原帖中文精译与推文细节
[推文 1] 非常酷的评估方法。只需向大模型提问“陆地还是海洋？”，并提供经纬度坐标文本。重复提问 16,200 次，并将结果绘制成图像。大模型确实知道答案，这源于对整个互联网信息的压缩。 [推文 2] 我们未来将花费更多时间去理解语言模型的输出。以下是一些想法、技巧与窍门： 写作：我成功尝试过的一个方法是，让大模型用 ASD-STE100 规范来解释事物。这是一种最初为航空航天维护文档开发的受控语言规范。大模型非常精通这种语言，它带有对精简写作风格的严苛约束，我发现这大大提升了可读性。有时我会稍微放宽要求，比如要求“达到 ASD-STE100 80% 的标准”，因为该规范确实相当严格。但还有更棒的： 图表/图像：与其阅读文字，不如让大模型生成图表。这些图表处理、解析和理解起来要容易得多。但还有更棒的： 网页：要求以“HTML”形式输出，从而获得一个美观且具备交互性的网页。大模型在前端开发方面越来越出色，能够创建漂亮的交互体验、动画等。但还有更棒的： 讲解视频：我最看好的输出格式是针对任意主题生成的完全定制/专属的讲解视频。可以尝试类似的指令：“创建一个关于 X 主题的 3b1b（3Blue1Brown）风格视频讲解。使用我的 ElevenLabs API 密钥进行语音旁白。”（后者需要 API 密钥，或者你可以让大模型帮你寻找使用本地算力的优质免费替代方案）。这已经开始奏效了！ 总结： - 随着大模型变得越来越强大，它们将自主完成越来越多的基础工作，而我们的很多工作将上升到更高层级的抽象，转向监督与理解。 - 幸运的是，大模型在此也能提供帮助。随着智能和代码变得日益过剩，你可以要求生成大型、定制、可即用即弃的软件产物（如 Web 应用、讲解视频），这在以前是完全不可想象的。大胆探索这一边界，你会大吃一惊。

How we contain Claude across products

Anthropic Engineering · 官方技术博客

【推荐理由】该文为构建企业级 AI Agent 提供了核心安全思路：从依赖用户监督转向构建底层隔离环境（如沙箱和 egress 控制）。对于研发团队而言，如何量化并限制 Agent 的“爆炸半径”是实现 AI 自动化落地的关键参考。

Anthropic 在本文中探讨了如何通过“限制爆炸半径”（Containment）而非单纯依赖人工监督来部署高能力 AI Agent。文章指出，随着 Agent 能力增强，传统的“人机回环”因用户审批疲劳（93%的通过率）而失效。Anthropic 转向通过沙箱、虚拟机和出口控制等技术手段强制设定访问边界。针对 claude.ai、Claude Code 和 Claude Cowork 三类产品，Anthropic 采取了差异化的隔离架构，旨在平衡 Agent 的高实用性与系统安全性，通过硬性防御机制降低潜在的破坏风险。

一年前，我们绝不会允许 Claude 拥有可能导致内部服务瘫痪的权限，但现在这已成为常态。部署风险由“故障概率”和“破坏程度”组成，随着 Agent 能力提升，我们必须通过限制其环境访问权限来控制“爆炸半径”。我们发现，依赖人类审批的监督方式存在严重的“审批疲劳”，用户往往会盲目点击通过。因此，我们重点转向了“容器化”策略，通过沙箱、虚拟机和出口控制等技术手段，从物理和逻辑层面限制 Agent 的行为边界，从而在保障安全的前提下释放 AI 的生产力。

Anthropic Engineering · 官方技术博客

过去一个月，我们调查了用户反馈的 Claude Code 性能下降问题。经排查，API 层未受影响，问题源于三个独立的工程变更：3月4日调整默认推理努力度导致质量下降；3月26日的会话清理 Bug 导致模型表现出重复和健忘；4月16日的系统提示词调整损害了代码质量。所有问题已于 4月20日修复。我们从未故意降低模型性能，未来将通过更严谨的评估机制，确保此类产品层面的性能波动不再发生。

Scaling Managed Agents: Decoupling the brain from the hands

Anthropic Engineering · 官方技术博客

【推荐理由】该架构为构建企业级 Agent 系统提供了极佳的解耦范式，特别适合需要长期运行、高可靠性的复杂任务场景。其“接口抽象化”的设计思路能有效降低模型迭代对业务逻辑的冲击，是构建可扩展 AI 应用的必读指南。

Anthropic 发布了“托管智能体（Managed Agents）”服务，旨在解决长周期任务中智能体架构的耦合问题。核心架构设计借鉴了操作系统虚拟化思想，将智能体拆解为 Session（会话日志）、Harness（执行循环）和 Sandbox（沙箱环境）三个独立接口。通过这种解耦，Anthropic 避免了将智能体视为“宠物（Pet）”式的单体维护模式，实现了各组件的独立演进与替换，从而适应模型能力提升带来的架构变化，确保系统能够承载未来未知的复杂任务。

Anthropic 推出 Managed Agents，通过将智能体的“大脑”（模型调用逻辑）与“手”（执行环境）解耦，构建了可长期运行的托管服务。该架构借鉴了操作系统对硬件的抽象设计，通过定义标准化的 Session、Harness 和 Sandbox 接口，使底层实现可以自由替换，而无需重构整个系统。这种设计不仅解决了模型因上下文限制产生的“焦虑”行为，还通过将单体容器架构转变为可替换的“牲畜（Cattle）”模式，显著提升了系统的可维护性与鲁棒性。

【为何关注】该案例展示了如何通过“去中介化”重构传统行业基础设施，是典型的“深科技+支付”创新。对于 AI 从业者而言，Piston 证明了深入垂直场景、利用数据闭环解决欺诈等高价值痛点，比单纯堆砌模型更能构建极高的商业护城河。

FPV Ventures 合伙人 Nikunj Kothari 领投了燃料支付平台 Piston 的 A 轮融资。Piston 通过绕过传统信用卡网络，利用自有支付轨道解决车队燃油欺诈问题，实现了支付量 8 倍增长及 98% 以上的客户留存率。

我长期以来一直痴迷于闭环支付，并一直在寻找能够解决实际问题的公司……很高兴终于投资了 Piston (piston.com) ⛽️。 仅在美国，每年在燃油上的支出就高达数千亿美元。大部分支出通过卡片（信用卡、燃油卡或内部卡）支付。然而，许多卡片甚至没有绑定特定驾驶员，极易被盗、被复制或滥用。车队所有者不仅要承担欺诈损失，还要耗费大量时间核对账目。加油站既要支付高昂的交换费，又无法与车队建立直接联系。许多公司试图优化现有基础设施，却未从底层逻辑进行重构。 仅靠制造一张更好的燃油卡无法解决问题。卡片本身就是症结所在，因此 Piston 决定彻底抛弃它。它通过自有支付轨道处理交易，无需任何网络或中间商。Piston 先向加油站付款，再向车队开具发票。每笔交易都绑定了特定的驾驶员、时间、地点和燃油类型，未来还将与车辆本身直接集成。 创始人亲身经历过这一痛点。@vik_sekhon 经营着自己的卡车车队，曾因燃油欺诈遭受真实损失；@Shivam2291 曾负责招聘数千名司机。两人联手创立了 Piston。最能证明 Piston 有效性的信号是：车队一旦切换到 Piston，燃油支出会立即自动下降。我看到了大量数据图表和客户评价直接印证了这一点。 客户的喜爱体现在指标上：支付量增长了 8 倍，商户网络扩大了 40 倍，留存率保持在 98% 以上。Piston 目前已覆盖全美 48 个州的 2,000 个加油站。车队目前无需支付任何费用，即可获得传统卡片系统无法提供的欺诈预防功能。加油站则获得了与车队直接对接的渠道，有助于建立忠诚度并提供周边产品。 为了扩大覆盖范围，Piston 现已直接与美国大多数加油站的 POS 系统集成。这使他们能够一次性接入数百个加油站，确保供应并满足其激增的需求。 很高兴能领投他们的 A 轮融资并加入董事会，与现有投资者 @sparkcapital 和 @pearvc 并肩作战。特别感谢 @arpans 去年将这个团队介绍给我！

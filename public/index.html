Andrej Karpathy 近期分享了关于 LLM 输出评估与交互形式的深刻见解。他指出模型通过压缩互联网数据已具备极强的地理常识，并建议通过 HTML 页面、交互式图表及定制化视频等高维媒介来提升对模型输出的理解效率。

【推文 1】很酷的评估方法。只需给 LLM 输入经纬度坐标，并询问“陆地还是水域？”。重复 16,200 次并绘制成图像。模型确实懂，这源于它们对互联网数据的压缩。 【推文 2】未来我们将花更多时间去理解语言模型的输出。以下是一些心得与技巧： 写作方面：我发现一个有效方法是要求 LLM 使用 ASD-STE100（一种最初为航空航天维护文档开发的受控语言规范）进行解释。LLM 对此非常精通，且该规范对简洁文风有严格限制，可读性极高。有时我会要求“80% 的 ASD-STE100 风格”，因为原规范过于严苛。但还有更好的方式： 图表/图像：与其写文字，不如让 LLM 生成图表，这更易于处理和理解。但还有更好的方式： 网页：要求以“HTML”格式输出，即可获得美观的交互式网页。LLM 在前端开发方面表现出色，能创建精美的动画体验。但还有更好的方式： 解释性视频：我最看好的是针对任意主题生成的完全定制化解释视频。尝试指令如：“创建一个 3b1b 风格的关于 X 的解释视频，使用我的 ElevenLabs API 密钥进行配音”。这确实已经开始奏效了！ 总结： - 随着 LLM 能力提升，它们将自主完成更多繁重工作，我们的重心将转向监督与理解。 - 幸运的是，LLM 本身也能辅助这一过程。随着智能与代码变得廉价，你可以要求生成过去无法想象的大型、定制化、一次性的软件制品（如网页应用、视频）。大胆尝试，你会感到惊喜。

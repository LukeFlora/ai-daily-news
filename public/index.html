How we contain Claude across products

Anthropic Engineering · 官方技术博客

【推荐理由】本文为 AI 工程化落地提供了极具价值的参考：它揭示了单纯依赖用户确认的监督模式在生产环境中的脆弱性，并明确了通过基础设施层（沙箱、网络隔离）进行“权限最小化”是实现高自主性智能体的必经之路，非常适合正在构建 Agent 产品的团队参考。

Anthropic 在本文中探讨了如何通过“限制爆炸半径”（Blast Radius）来安全部署 Claude 智能体。核心观点认为，随着模型能力增强，单纯依赖“人在回路”（Human-in-the-loop）的监督机制因用户疲劳（93%的批准率）而失效。因此，Anthropic 转向以“容器化隔离”（Containment）为核心的架构，通过沙箱、虚拟机和出站流量控制来限制智能体的权限边界。文章总结了其在 claude.ai、Claude Code 和 Claude Cowork 三款产品中积累的安全工程经验，强调了在提升智能体自主性与控制潜在破坏力之间的平衡策略。

十二个月前，我们绝不会允许 Claude 拥有足以瘫痪内部服务的权限，但现在这已成为常态。风险由“故障概率”和“潜在破坏力”组成，随着模型能力提升，我们必须通过限制“爆炸半径”来控制后者。我们发现，依赖用户手动批准的监督模式存在严重的“批准疲劳”，用户往往会盲目点击。因此，我们重点转向了容器化隔离，通过沙箱、虚拟机和出口控制来限制智能体的操作边界。针对 claude.ai、Claude Code 和 Claude Cowork 等不同产品，我们构建了差异化的隔离架构，以应对用户误用、模型越狱及系统漏洞等安全挑战。

Scaling Managed Agents: Decoupling the brain from the hands

Anthropic Engineering · 官方技术博客

【推荐理由】该文为构建生产级智能体提供了极佳的架构参考，特别是通过接口抽象实现“大脑”与“执行层”解耦的思路，能有效降低模型升级带来的重构成本。对于需要处理长周期复杂任务的研发团队，建议借鉴其将执行环境与会话状态分离的设计，以提升系统的容错率和可维护性。

Anthropic 发布了“托管智能体（Managed Agents）”服务，旨在解决长周期智能体任务中的架构耦合问题。核心设计理念借鉴了操作系统对硬件的虚拟化思路，将智能体拆解为 Session（会话日志）、Harness（执行循环）和 Sandbox（沙箱环境）三个独立接口。通过这种解耦，Anthropic 避免了将单一容器视为“宠物”式维护的困境，实现了组件的可替换性，确保系统能适应模型能力的快速迭代，并有效解决了模型“上下文焦虑”等行为随模型升级而失效的问题。

Anthropic 推出 Managed Agents，通过将智能体的“大脑”（模型）与“双手”（执行环境）解耦，构建了可长期运行的托管服务。该架构借鉴了操作系统抽象化硬件的模式，将智能体拆分为会话、执行循环和沙箱三个独立接口。这种设计不仅解决了因模型能力提升导致旧版执行逻辑失效的问题，还通过消除容器间的强耦合，将原本难以维护的“宠物式”单体服务转变为可扩展、可替换的“牛群式”基础设施，提升了系统的鲁棒性。

我们都需要更新对 Agent 工作负载的认知，结合 Agent 集群、更强的计算机操作能力、新一代 API 与 MCP 标准，以及 Muse 或 Instinct 等新形态设备，再加上垂直行业 Agent 和后台工作流 Agent，这些产品正在涌现。 我们将在职业和个人生活中，将 Agent 应用于比最初想象中多得多的任务。Agent 在后台为我们搜索信息和处理工作的体量，将是此前单次 Prompt 交互所能想象的 100 倍。 未来，Agent 将 24/7 全天候为你精准招聘人才，从客户业务的每个信号中寻找推销时机，处理每一份会议纪要以提取产品洞察，审查每一行代码以发现安全漏洞，对系统进行暴力测试，以及执行数百种其他任务。 我们目前可能只触及了这些 Agent 形态、部署方式、管理模式及预算规划等全貌的 1% 左右，但这种规模化的变革已不可阻挡。 在一个 Agent 使用系统的频率比人类高出 100 倍的世界里，保护企业数据将成为 21 世纪最复杂的安全与治理挑战之一。 重要的是，在 AI 时代，安全与生产力提升是密不可分的。如果你给予 Agent 过多不受限制的信息访问权限，将难以真正控制和保护数据；反之，如果完全封锁，你将无法从 AI 中获得真正的生产力提升。 我们需要通过现代化手段，以智能化方式保护企业系统、环境以及结构化和非结构化数据。 以 Box 为例，我们正在构建保护企业数据及 Agent 使用信息的新型智能方案。Box Shield 的最新更新提供了基于文档分类级别的细粒度控制，限制 Agent 可操作的内容。我们还在开发其他功能，以自动检测并预警（或拦截）Agent 对数据的异常访问或使用行为。 这仅仅是个开始。整个行业正迎来海量创新——从 OpenAI 或 Anthropic 等实验室，到 Palo Alto Networks、Cisco、CrowdStrike、Okta 等安全平台，再到 Enclave、Method、Alterion、Runlayer 等初创公司，都在重新思考 AI Agent 时代的信息保护之道。未来充满机遇与挑战。

FPV Ventures 合伙人 Nikunj Kothari 领投了燃料支付平台 Piston 的 A 轮融资。Piston 通过绕过传统信用卡网络，利用自有支付轨道解决车队燃油欺诈问题，实现了支付量 8 倍增长及 98% 以上的客户留存率。

我长期以来一直痴迷于闭环支付，并一直在寻找一家试图解决实际问题的公司……很高兴最终投资了 Piston (piston.com) ⛽️ 仅美国在燃油上的支出就高达数千亿美元。大部分支出通过卡片（信用卡、燃油卡或内部卡）完成。然而，许多卡片甚至没有绑定特定驾驶员，经常被盗、被复制或滥用。车队所有者不得不承担欺诈损失，并花费大量时间核对账目。加油站为了接受这些卡片必须支付交换费，却与另一端的车队没有任何直接联系。许多公司试图优化这种基础设施，却没能从源头思考问题。 你无法仅仅通过制造一张更好的燃油卡来解决这个问题。卡片本身就是问题所在，因此 Piston 决定彻底抛弃它。它将支付转移到自己的轨道上，无需网络或任何中间商。Piston 先向加油站付款，然后向车队开具发票。每笔交易都与特定的驾驶员绑定，并附带时间、地点和燃油类型，很快它还将与车辆本身集成。 创始人亲身经历过这个问题。Vik Sekhon 经营着自己的卡车车队，他的车队曾因燃油欺诈损失真金白银。Shivam 在两人联手打造 Piston 之前，曾负责招聘数千名驾驶员。衡量 Piston 对车队有效性的最佳信号是：当他们切换到 Piston 时，燃油支出会自动下降。我见过许多直接证明这一点的图表和客户评价。 客户的喜爱体现在指标上。支付量增长了 8 倍，商户网络增长了 40 倍，而留存率保持在 98% 以上。Piston 目前已覆盖全美 48 个州的 2,000 个加油站。车队目前无需支付任何费用即可获得防欺诈保护，这是基于卡片的系统无法提供的。加油站则获得了与车队直接接触的机会，有助于建立忠诚度并提供周边产品。 为了扩大覆盖范围，Piston 现在直接与美国大多数加油站的 POS 系统集成。这使他们能够一次性激活数百个加油站，确保供应，从而满足其日益增长的需求。 很高兴能领投他们的 A 轮融资并加入董事会，与现有投资者 Spark Capital 和 Pear VC 并肩作战。特别感谢 Arpan 去年将我介绍给这个团队！
